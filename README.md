# 灵动参数管家

参数管理平台，目标是实现应用参数与数据库参数发布的自动化、可视化和版本管理。当前版本先实现系统入口、创建系统、接口错误处理及工作区模板，为后续参数发布业务提供清晰基础。

## 启动与验证

```sh
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm lint
pnpm format:check
```

使用 Vite、React 19、TypeScript、Ant Design、UnoCSS、React Router、TanStack Query 和 Redux Toolkit。版本以 package.json 和 pnpm-lock.yaml 为准。

Node 使用 22.12.0 或更高版本。为兼容 Node 22.12，React Router 固定为 7.18.5（该包要求 Node ≥20）；浏览器路由和使用登录 middleware 的测试路由显式启用 `future.v8_middleware`，保留登录检查先于并行 loader 的行为。继续使用 `react-router` 和 `react-router/dom` 导入入口，无需安装 `react-router-dom`。

`pnpm test` 通过 `--experimental-strip-types` 直接加载 TypeScript，并使用 Node 22.12 支持的 `module.register` 注册路径别名；该版本可能输出实验功能提示，不影响测试结果。

## 业务范围

本期保留系统列表、创建系统、应用分组列表和数据库类型清单。应用参数已接入环境列表与可编辑配置面板；搜索、检查、异常项、比对等入口保留；发布、审批及快照写入暂不实现。

环境参数面板使用 `MonacoEditor` 编辑 YAML，支持高亮、行号、查找、复制和撤销；编辑器按需加载并跟随平台主题，模型按系统、应用和环境隔离。空白配置同样显示可编辑的 Monaco 编辑框，拖拽、折叠和放大沿用原面板布局。内网 Worker 配置和组件用法见 [Monaco 编辑器说明](src/components/MonacoEditor/README.md)。

### 应用环境参数面板

环境列表暂约定为 `GET /api/applications/environments?systemName=…&appName=…`，响应为环境对象数组。API 只负责 HTTP 契约，Mock 由统一 adapter 按需加载；接真实服务时需对齐地址。查询按系统和应用隔离，30 秒内复用缓存，按 `envOrder` 升序展示，默认选中排序后的前三个环境。loader 完成系统访问校验后并行预取清单和环境；页面沿用同一缓存和取消信号，不复制服务端配置到 Redux。移除独立的“刷新环境配置”区域，加载失败仍可通过错误提示重试。

业务应用（`appType=0`）展示历史记录、快照生成、最新和运行时快照版本、上传、创建快照、发布、非生产环境一键发布、检查及刷新差异数；版本以“运行时 / 最新”的顺序紧凑展示，按钮可展开快照创建信息。发布与一键发布使用组合按钮，检查与刷新差异数使用组合按钮，差异数仅在大于 0 时以组合按钮右上角徽标展示，微调偏移并预留右侧间距。工具栏与环境标识保持单行，环境描述不再展示，生产和审批信息收纳到环境标识提示中；窄面板可横向滚动工具栏。环境操作 Tooltip、环境标识提示及版本 Popover 使用可视区域对齐，并启用无箭头距离阈值的平移避让；触发按钮被部分裁切时，浮层也不会因保持箭头距离而撑宽 body。公共应用（`appType=1`）仅展示历史记录、上传、批量创建快照和批量发布快照。生产标记来自 `isPrd`，测试审批标记来自 `approvalRequiredFlag`，都不作为访问授权依据。

当前配置可直接编辑，保留缩进和行号，空白配置同样可以输入内容。草稿由当前应用工作区按环境隔离，清空内容仍保留为空字符串，取消勾选、折叠和放大不会丢失；切换应用或系统、离开页面或刷新浏览器后清除。草稿不写入服务端查询缓存，有改动时显示“本地修改（未保存）”；保存接口尚未接入。历史、上传、快照、发布、检查和独立差异刷新接口尚未约定，对应操作按钮均保持启用，点击提示功能尚未接入；不产生模拟写入成功。`runtimeDifferNum` 为零或负数时不展示差异徽标，不推断负数状态码含义。403、404 优先于已有配置；普通刷新失败保留缓存并提供重试。环境面板继续支持调宽、折叠、放大，所有新增样式使用组件内 UnoCSS 工具类。

项目仅支持 PC，根应用统一设置 1280px 最小宽度；窗口不足该宽度时保留桌面布局，通过横向滚动查看，不提供移动端布局或窄屏列表抽屉。显示偏好中的“紧凑布局”仅调整桌面的间距与面板样式，不代表移动端模式。

登录页位于 `/login`，暂时选择“平台人员 / 普通用户”和“办公网 / 互联网 / 业务网”即可登录，使用给定示例资料，默认普通用户与办公网；角色和网络独立选择，所选网络随完整用户资料保存并在个人资料卡片展示。`localStorage` 的 `parameter-management:login` 记录统一保存版本、登录标志和完整用户资料；仅检查会话版本与登录标志，不对用户资料做运行时字段校验；记录缺失、JSON 无法解析、版本不支持或无登录标志均视为未登录。根路由 `restoreLoginMiddleware` 每次导航读取登录资料，扁平字段内容相同则保留原 Redux 引用、不重复 dispatch，资料变化或登录失效时才同步，不限制访问；登录页等公开页面直接注册在根路由下，后续小工具、产品介绍等页面放在同级。首页和系统工作区统一放在无路径的受保护分组中，由 `loginMiddleware` 在并行业务 loader 前检查登录，未登录跳转到带 `redirect` 参数的登录页；新增受保护业务页应放入该分组，系统访问由系统父路由 middleware 在业务 loader 前统一校验。登录成功持久化资料后整页替换到原路径和查询参数，由根 middleware 恢复 Redux，释放旧身份请求、缓存和草稿，首次直达时也保留锚点。刷新和再次进入页面时从本地记录恢复 Redux；无论是否已登录，均可主动访问登录页，回跳仅在提交登录成功后执行。回跳仅允许站内地址，登录页自身及非法地址回退首页；存储写入失败留在登录页提示重试。

`userType` 为平台角色（0 平台人员、1 普通用户），`netEnv` 为登录网络（0 办公网、1 互联网、2 业务网），`cmbUserType` 为员工类型（1、2 为正式员工），这些字段独立保存；仅平台角色参与本期访问规则，员工类型、网络和组织信息不参与授权。平台人员可进入所有存在的系统，普通用户以所有系统查询响应的 `userRelation === true` 确认已加入；V/D/R 本期只展示，不区分具体操作。系统 middleware 按工作区进入边界调用 `requireSystemAccess`，保留 403、404 和网络错误处理。当前本地登录仅用于流程演示，接入真实后端时须由服务端校验登录及授权。

开发环境的“参数项”页面保留原有 Loading 效果图库，保留的页面数据加载和平面方案在同一网格中完整展示，不按 Tab 或分段控件筛选；生产环境仍显示参数项占位工作区。演示代码与组件专用动画保留在原有目录中。

## 显示偏好

页头右侧仅显示可点击的圆形姓氏头像，姓名通过悬停提示和无障碍标签提供；展开菜单仅显示左右对齐的用户姓名和一事通 ID（不加字段前缀），操作项保持等高、图标和文字统一对齐，退出登录单独分组；点击“个人资料”按需加载只读弹窗，使用随主题变化的纹理封面与圆形头像，平台角色和登录网络以标签并排展示，身份采用填色标签区分平台人员与普通用户，网络同样采用无描边柔和填色，办公网使用青色、互联网使用蓝色、业务网跟随主题色，并搭配不同图标，底部保留账号信息，直属部门突出显示并保留完整上级路径，长内容可自然换行；不显示标题和关闭按钮，支持遮罩及 Esc 关闭，不展示员工类型。“用户配置”打开原有全局偏好抽屉；“退出登录”移除本地登录记录、清空 Redux 用户资料、关闭配置抽屉并取消在途和排队设置请求，再整页替换至登录页，释放业务查询缓存及临时草稿。再次登录可回到退出前的完整地址。移除登录记录失败时保留身份并提示重试；退出不删除显示偏好与业务 Mock 数据。主题、布局、圆角和图标显示等偏好独立保留；Store 注册 preferences 和 user Slice。启动时读取一次显示配置，失败后使用回退显示并提供独立重试；显示配置读取独立于登录检查。

### 完整配置保存

`userSetting.theme` 是后续参数编辑器主题，原样保存，不影响平台主题。`themeMode` 驱动平台浅色、暗色和跟随系统，缺失时使用现有默认值。`defaultCheckAllEnvTag` 和未知字段均保留。

首屏配色在 HTML 头部同步执行，先于外部 JS/CSS 加载，避免慢网络下出现默认白色画布。Vite 插件从现有主题生成背景与文字颜色，并与 Store 共用缓存键及校验规则；这里只直接设置最小根节点样式，因为 UnoCSS 此时尚未下载，不新增样式文件。React 接管后仍通过原有主题变量更新页面。

React 阶段由 `AppThemeProvider` 在首次提交时补齐完整主题变量，随后响应配置、圆角预览及系统外观变化；`main.tsx` 通过 `startUserSettingsEffects` 安装唯一的配置 Store 订阅，统一处理主题/图标/控件圆角启动缓存、保存成功广播和排队刷新；不再额外应用一次完整主题。缓存按字段分别去重和处理失败，HMR 时统一释放通知通道、浏览器事件及 Store 订阅，并取消在途和排队的配置请求。HTML 与 Store 各读一次相同缓存：前者决定提前显示的颜色，后者保留用户的 `system` 等原始选择，不能用 HTML 中已解析的浅色/暗色替代它。

构建插件源码位于 `build/`，现有测试位于 `scripts/`。生产部署仅发布 `pnpm build` 生成的 `dist/`；插件在构建时将最小主题脚本写入 HTML，不将构建工具或测试文件复制到产物。

`build/bootstrap-plugin.mjs` 统一执行一次 HTML 转换，按字符集、启动异常监听、主题脚本、图标脚本和图标样式的顺序注入；主题与图标初始化函数各自独立，Vite 配置无需协调两个插件的顺序。主题脚本通过 Vite 的 HTML 标签注入接口自动放入头部，不依赖模板里的注释标记。UTF-8 声明由插件统一放在脚本之前，删除或调整原有声明也不会破坏首屏注入；配色执行失败时由正式应用主题接管。

`parameter-management:bootstrap-theme:v1` 保存当前浏览器最近一次确认的主题，设置接口读取成功后校准。乐观值、配置损坏和读取失败不覆盖缓存，`system` 原样保存。

首屏加载图标随 HTML 内联返回。`build/bootstrap-plugin.mjs` 在 Vite 开发服务器或生产构建中静态渲染现有 SVG 和共享布局，再用现有 UnoCSS 配置生成内联工具类样式；浏览器显示图标时不必先下载 React。专用动画关键帧仍由原 SVG 组件内嵌，不增加样式文件。

HTML 包含所有内置图标，头部脚本读取 `parameter-management:bootstrap-loading:v1`，经白名单校验后只显示其中一款；非法缓存或存储不可用时回退品牌描边。该缓存保存最近一次服务端确认的 `loadingStyle`，只作首次配置读取前的显示提示，不代表配置已经初始化。读取失败、乐观选择和保存失败不会用未确认值覆盖缓存；连续保存中较早成功的响应仍会更新缓存。

启动画面放在 `root` 外作为兄弟节点，资源下载和根级等待期间保留原 SVG，避免 React 重建节点导致动画重新播放。`BootstrapLoadingProvider` 记录这份画面是否仍在显示；此时 `ResourceLoading` 返回空内容，让外部画面继续提供加载提示。页面骨架、正文或错误页提交后，`BootstrapLoadingHandoff` 在布局 Effect 中移除 HTML 画面，并通知 Provider 结束启动阶段。配置返回只影响后续 React 图标及下次启动缓存，不切换当前 HTML 动画的方案。

生产入口的主样式链接先以 `media="print"` 下载，避免阻塞内联图标绘制。头部脚本在链接解析前安装捕获监听，加载成功或失败后切回 `all` 并标记完成；`main.tsx` 等待所有被标记的链接结束，再挂载 React，减少未应用样式的页面闪现。此前已经结束的链接直接通过，失败也不会造成永久等待。HTML 解析完成且所有标记链接结束后，头部脚本释放捕获监听。模板显式指定的媒体条件保持原语义，页面懒加载样式仍由 Vite 管理。

路由加载和配置读取不等待上述样式交接，仍与样式下载并行。React 挂载后，根 `HydrateFallback`、`App` 和路由错误页在首次配置等待结束前都通过 `ResourceLoading` 保留 HTML 原动画，不提前展示骨架或正文，避免缓存与服务端配置不一致时骨架发生明暗、布局和导航宽度变化。配置成功或失败后，页面已就绪则直接展示正文或错误页；父级 loader 或页面模块仍在等待时，`InitialRouteFallback` 才按目标 URL 展示静态骨架。没有静态骨架时继续使用 HTML 原动画；独立渲染且没有 HTML 画面时，由 React 图标提供回退。后续配置重试、后台同步和导航不会重新进入首次配置等待，导航继续使用统一轻量路由骨架。

首屏骨架包含基础布局：站点首页显示页头与内容区，系统工作区额外显示主导航占位，再在内容区渲染统一的普通骨架。`layouts/LayoutFrame.tsx` 让骨架与正式页面共用视口、导航和内容容器，保持最小宽度、布局间距、紧凑模式及导航宽度一致；页内导航仍只替换内容区，不重复外壳。

首屏骨架只读取首次等待结束后的显示偏好及公开路由配置，不查询或展示受保护业务数据；正式工作区仍受原 loader 和系统布局校验约束。配置读取失败或超时也会结束等待，以回退配置继续展示骨架或页面，正常工作区提供重试入口；不会用失败回退值覆盖启动缓存。主题通过布局 Effect 在绘制前应用，与骨架、正文或错误页的启动交接在同一次提交完成；仍可能存在启动背景到最终主题的明暗变化，但不会先展示未校准的骨架。HMR 若发生在样式等待期间，会标记旧入口失效，忽略它随后完成的挂载回调，而不会取消浏览器的样式下载。

### 首屏依赖与骨架边界

轻量路由骨架集中在 `src/components/RouteSkeleton/`：`index.tsx` 的 `RouteSkeleton` 提供所有页面通用的内容占位，内部 `HeaderSkeleton` 和 `NavigationSkeleton` 负责首次等待的外壳占位。`src/router/skeletons.tsx` 只保留根回退的配置等待、布局组装和启动交接。页面路由直接声明 `HydrateFallback: RouteSkeleton`，导航加载也从目标路由的 `HydrateFallback` 读取组件，不在 `handle` 中重复登记骨架。不再静态登记业务骨架或清单分栏参数，也不读取分栏尺寸缓存。

业务数据骨架随页面模块加载：系统卡片骨架放在 `pages/SystemsHome/components/SystemsHomeSkeleton.tsx`；应用和数据库复用 `components/CollectionSkeleton/index.tsx`，由各自页面传入标题、尺寸缓存键等参数。页面仅在查询首次无数据（`isPending`）时展示业务骨架，已有数据的后台刷新保留正文和交互状态，失败仍保留错误与重试入口。概览页直接消费已授权的系统上下文，没有独立数据等待，因此无需专用骨架。

现有 loader 仍等待必要授权，并按原缓存策略预取数据；冷启动数据已经准备好时，页面可以直接显示正文，不必经过业务骨架。分栏业务骨架复用 `SplitPane` 的轻量展示层和只读尺寸解析，不注册拖拽、快捷键、尺寸观察或偏好写入；这些依赖均不会由路由骨架引入。骨架布局样式全部沿用 UnoCSS。

根组件只挂载设置面板的轻量入口，完整抽屉和表单首次打开时动态下载；下载期间可关闭，失败提供“刷新页面重试”，恢复部署资源失效或浏览器缓存的模块下载错误。首次激活后保留组件挂载，以维护关闭动画、保存反馈和再次打开行为。设置请求、串行保存及失败回退仍由现有 thunk 管理。

错误处理分为启动、整页和局部三层。HTML 中的 `failure-bootstrap` 在模块入口之前监听未处理的执行异常和模块脚本失败，显示独立于 React、主 JS/CSS 的启动失败提示与刷新按钮；普通图片失败不会触发。首次骨架、正文或错误页提交后，由启动交接事件解除这些监听，后续业务异常不会再进入启动失败状态。启动兜底不设置超时、不自动刷新，也不接管请求缓存、权限或业务错误；开发环境继续保留 Vite overlay。

React 容错采用 `react-error-boundary 6.1.6`（MIT，与当前 React 19 类型兼容，无额外运行时依赖）。相比继续维护多个类边界，库统一提供 fallback、重置和模型切换恢复；HTML 启动兜底仍由浏览器原生事件负责。顶层边界放在业务 Provider 外，失败反馈不读取 Redux、Router 或主题 Context；路由保留 403/404 语义，其余整页错误共享反馈。两个 Monaco 入口分别设置局部边界，失败反馈保留尺寸及父层草稿状态；重试会重新挂载编辑器，不承诺保留其内部撤销历史。模型路径变化后自动解除旧文档的错误状态，编辑内容变化不自动触发重试。

个人资料与设置面板共用 `DeferredPanel`，首次激活后继续保留挂载；等待或失败时可关闭及按 Escape 关闭。普通渲染错误提供重试，模块下载失败仅提供刷新，因为重置边界不会重新调用已缓存的 lazy 加载函数；刷新前应注意未保存内容。事件处理、HTTP 请求、串行保存和失败回退仍由原事件、Query 或 thunk 负责。边界沿用 React 的控制台错误诊断，界面展示失败原因，提供可展开的堆栈与 cause 链及复制按钮；详情仅以纯文本呈现，不展开请求配置或响应正文，也不增加外部遥测。完整 React 诊断界面在失败时按需加载；正常等待使用与收起操作栏等高的占位，避免纯文本原因先闪现并推动主体，只有详情资源本身下载失败才显示基本错误原因。HTML 启动失败页使用跟随浅深主题的开放式双栏，内联 SVG 以抽象窗口和异常徽标表达不可显示状态，不暗示具体故障原因；提供刷新主操作与技术支持按钮，下方可展开失败原因。启动失败页保留原生按钮，在主 JS/CSS 不可用时仍可操作；按钮颜色、交互表面和阴影在构建时读取当前 Ant Design 主题，hover/active/focus 样式通过 UnoCSS 随 HTML 内联。控件圆角使用按用户隔离的最近服务端确认缓存，首次访问或缓存非法时回退默认值；乐观预览和失败保存不写入缓存。这些样式和圆角提示使 HTML 增加约 0.65 KB gzip，HTML 预算相应设为 11.8 KB，JS/CSS 预算不变。技术支持暂不绑定跳转，由后续业务接入实际地址；保留首次失败及模块资源地址，错误早于 body 解析时在 DOM 就绪后补写。该启动页不提供复制按钮，文本可手动选择；React 整页兜底与启动页共享静态插画，使用 Ant Design Button 提供刷新、预留技术支持，以及路由场景下的返回系统列表；诊断区以错误摘要作为默认收起的入口，提供按钮原位复制反馈；展开后以调用列表显示，并可切换未格式化的诊断文本。局部错误的复制功能保留，剪贴板不可用时提示手动选择文本。后续升级该库需重新验证 React 兼容、资源失败、重试及首屏预算；不再需要多处局部边界时可移除该依赖。

诊断原文指提取后的文本，不是异常对象的全量序列化：仅读取 `name`、`message`、`stack`、`status`、`code`、`cause` 和数组形式的 `errors`，不展开请求配置或响应正文。每个字段独立容错，单个 getter 失败仍保留其他可读字段；聚合异常兼容跨 realm，同一路径的循环引用会标记。提取层仅保留极端资源保护：最多 262,144 字符、32 层原因深度、总计 2,000 个异常节点，不再限制每个聚合数组为 20 项；这些是本项目的保护阈值，非通用标准。触及限制会明确提示，并说明复制内容同样受提取保护约束。提取函数会序列化到启动 HTML，不能依赖外部模块闭包。

整页调用列表参考 `stacktrace-parser` 的多格式分支思路实现，无新增依赖。兼容常见 V8/Node、Gecko/JSC 和源协议；只简化本地开发 origin，查询串及 hash 原样保留。未知、复杂 eval/native 与超长行保留原文，整体解析失败时直接显示诊断原文；“查看原文”与复制共用同一份提取文本。整页的格式化/原文视图另设预览额度：首批最多 60 行或 16,000 字符，通过“继续显示”按相同额度追加；切换视图保留预览进度，异常文本变化时从首批开始。预览切片不修改提取文本，复制不受当前预览范围限制。整页详情自然撑开，仅由页面纵向滚动，局部错误面板沿用原有交互。

每次生产构建通过 `build/startup-budget-plugin.mjs` 检查真实入口的静态依赖闭包，包含共享 chunk 并去重，不计入动态页面。预算为每个文件分别 gzip 后求和：静态 JS 302 KB、主 CSS 20 KB、HTML 11.8 KB（KB 按 1000 字节）；超预算时构建失败。预算包含诊断入口及独立启动失败页，完整 React 详情与格式化模块仍禁止进入首屏静态闭包。路由状态页的三种主题 SVG 插画同步引入，避免恢复界面额外等待模块下载；实测相较懒加载增加约 2 KB gzip 的同步 JS，仍沿用 302 KB 门禁，不为此次调整放宽预算。启动卡片仅内联本地图标与 UnoCSS，三个同步启动脚本复用当前 Vite 压缩器缩小体积，不增加运行时依赖。完整报告输出到 `dist/startup-report.json`，这些数字不代表浏览器实测耗时，也不包含目标页面及启动请求触发的动态模块。

构建还禁止设置表单、完整设置抽屉、交互分栏 `SplitPane`、业务分栏骨架 `CollectionSkeleton`、业务页面及 Mock 数据回流入口静态依赖；错误与状态页及其插画、唯一 Mock adapter 和轻量配置保留同步接入。调整预算前先检查依赖报告，不通过手工拆包把同步依赖移出统计。新增业务需同时验证首页、业务深链接和首次打开面板的加载行为。

首次初始化、重试和后台同步使用 `GET /api/user-settings`，保存使用 `PUT`，不传递个人身份参数。保存前读取完整 `userSetting` 文档，再合并平台字段，保留编辑器设置及未知字段；非法 JSON 禁止覆盖。

设置保留即时预览、乐观更新、串行保存、失败回退和显式重试。跨页签只广播显示设置变更通知，接收方重新读取接口，不广播配置正文。取消在途请求时也会拦截尚未发送的排队写入。

用户设置抽屉按「外观」和「布局」分组：外观包含主题、导航配色和数据加载图标，布局包含布局模式、间距与圆角、菜单显示。标签内容独立滚动，标签栏和保存反馈保持可见；无遮罩抽屉使用非模态语义，允许键盘返回背景。滑块只在完成交互后保存，数值输入在失焦或按回车后提交，紧凑布局说明会保留并展示标准布局已保存的间距。所有布局样式沿用 UnoCSS，没有新增样式表。

## 系统列表与创建

首页 `/` 通过“我的系统 / 所有系统”页签切换，两者共用顶部强调线、系统资料、双参数入口和底部摘要的卡片结构，1280px 起每行四张。新增系统仅在“我的系统”工具栏显示。我的系统搜索和角色筛选不显示外部文字标签，保留输入提示与无障碍名称；工具栏另展示“新增记录”按钮，弹窗查询功能待接入。我的系统接口返回完整数组，搜索、角色筛选和分页在前端完成，翻页不会请求接口。所有系统筛选栏仅保留无外部文字标签的搜索框与查询按钮，使用服务端分页，输入关键词后点击查询或按 Enter；翻页、调整每页条数均请求相应页。两个页签独立保存查询及分页状态，隐藏页签不主动请求。

系统显示名称、描述、架构办子系统编码、重要性等级、负责人、所属科室/室组、指定审批人、应用数与参数类型数。我的系统卡片右上角展示系统管理、用户权限管理、退出系统三个图标按钮，保持启用并通过悬停提示说明功能待接入；点击系统名称查看完整资料和人员编号。所有系统仍通过右上角详情按钮查看资料。`systemDesc` 虽为 HTML 字符串，只提取文本展示，不注入页面。我的系统角色 `V/D/R` 分别展示为观察者/开发者/系统负责人；所有系统的 `userRelation` 直接决定加入状态。工作区访问统一由 `requireSystemAccess` 查询所有系统并检查最新 `userRelation`，不从组织、负责人或编号推导权限。

新增系统使用 Modal + Form，英文名、中文名、架构编码必填；描述、科室、室组、重要性和审批人可选。不从用户资料自动填写负责人或角色，关联由创建接口所属服务处理。

模拟服务保留去除首尾空格、必填及重复校验，重复英文名或架构编码返回 409。成功后使 `systems` 前缀下两份清单同时失效并回到我的系统首页，新系统的应用及参数类型数量为 0。模拟服务将新系统放在清单首位，记录创建关系为 R，缺少真实身份时 `ystId` 留空，不填造员工编号。失败保留输入，提交中防止重复提交。

目录视觉遵循用户提供的两张参考图，沿用现有主题、字体和圆角，卡片参数入口使用较大的图标和完整按钮，底部集中展示角色、描述、统计和组织。详情和工作区入口已实现；系统管理、用户权限管理、退出系统及新增记录查询仅预留按钮。所有样式使用页面就近的 UnoCSS 工具类，无新增样式表。示例关系仍为 CAC（R）、CACTEST1（V）与 ParamPlat（D）；接后端时替换为真实目录响应。全局外壳仍沿用项目现有的 1280px 最小宽度。

分页接口暂约定为 `GET /api/systems/page`，请求 `pageNum`（从 1 开始）、`pageSize`、`keyword`、可选 `userRelation`，响应 `{ records, total, pageNum, pageSize }`。Mock 先筛选再分页，总量缩小或超出尾页时返回有效页码。所有系统的页面直接显示接口 records 和 total，不在前端二次过滤或切片；缓存键包含全部查询维度，切页取消旧请求，不把其他页当作当前页展示。首页 loader 只预取默认的我的系统，工作区切换器统一使用我的系统接口；工作区 loader 重跑时复用目录缓存，目录写入通过查询失效触发更新。

## 架构与路由

```text
src/
  api/          业务接口地址、请求参数、HTTP 调用
  http/         Axios、Mock 接入点、取消、HTTP 错误
  queries/      查询键、缓存、失效和列表服务组装
  mocks/        场景、模拟数据、接口响应、版本化存储
  store/        Redux 装配、显示偏好同步
    slices/     preferences Slice
  pages/        大驼峰页面目录及私有组件
  components/   项目内复用组件，复杂组件内部按职责拆分
  layouts/      页面外壳、导航和用户设置抽屉
  providers/    全局 Provider
  router/       路由配置、loader、懒加载、静态骨架
  hooks/        全局 Hooks
  contexts/     已校验的系统工作区上下文
  types/        共享业务类型
```

不创建 features 总目录或页面/组件汇总 barrel。详见 AGENTS.md。

### 路径别名

`@/` 指向 `src/`，例如 `import { useAppSelector } from '@/store/hooks'`。
跨模块引用使用别名，页面或组件内部的私有文件继续使用短相对路径。
Vite alias 与 TypeScript paths 保持一致；`pnpm test` 通过 `scripts/helpers/register-alias.mjs` 注册 Node 解析钩子，使直接加载源码的测试支持同一别名，无需新增依赖。
首屏构建插件直接复用的少量模块保留相对路径，因为它们在 Vite 配置加载阶段执行，早于应用 alias 生效。
由 Node 直接加载的模块保留 `.ts` 扩展名；页面仍通过动态 import 按需加载。

### 分平台路由配置

应用入口异步加载 NProgress，由 `src/router/progress.ts` 统一订阅 Router：后续导航进入 loading/submitting 时开始，回到 idle 时完成，覆盖授权、loader、跨布局、重定向与取消；连续等待不重复启动。首次初始化仍沿用启动画面，HMR 取消订阅并清理进度条。进度仅表示等待，不代表实际百分比；关闭旋转图标，顶部 2px 主题色细线配合末端柔光，立即起步、每 450ms 缓慢推进，完成后平滑淡出。外观通过局部 UnoCSS 模板表达，无新增样式文件。`RouteOutlet` 仅负责同布局目标骨架，延迟 250ms 展示以减少闪烁，等待期间不提前挂载未授权的系统内容。

`src/router/application.ts` 定义应用参数路由，`src/router/database.ts` 定义数据库参数路由。两个文件各自维护路径、菜单顺序、标题、图标、懒加载页面及 loader 函数，公共类型放在 `src/router/types.ts`。导航直接使用对应平台配置，通过 `generatePath(path)` 省略可选参数生成菜单入口，无需额外维护 `to` 字段。UnoCSS 从完整图标类名提取样式。配置不静态导入业务页面。

`routes.tsx` 装配根、站点和系统布局，直接分别挂载两个平台的配置，只补齐共用的静态骨架、错误边界和页面懒加载。业务路由只配置匹配路径，不手写 `id`；仅 `site`、`system`、`workspace` 布局保留显式 ID，用于加载骨架定位。新增路由只需修改所属平台清单，无需再经过中间文件转发或按平台筛选。所有菜单均通过链接进入页面；应用与数据库的设置地址进入 `SystemSettings` 页面，目前保留工作区占位。页头用户菜单中的“用户配置”独立打开全局偏好抽屉。

| 路径                                                           | 用途                 |
| -------------------------------------------------------------- | -------------------- |
| `/`                                                            | 系统列表             |
| `/systems/:systemName`                                         | 默认跳转总览         |
| `/systems/:systemName/overview`                                | 应用平台总览         |
| `/systems/:systemName/application/:appName?`                   | 应用清单与选中应用   |
| `/systems/:systemName/db/:paramTypeName?`                      | 数据库类型与选中类型 |
| `/systems/:systemName/setting`、`db/setting`                   | 设置页面             |
| 系统下 params/search/inspect/exception/compare/apps-comparison | 后续业务占位         |

系统、应用和类型动态段统一 encodeURIComponent。`setting` 是数据库保留名称。切换系统或平台进入目标平台默认页，不带旧选中项。URL 是选择状态的唯一来源。部署服务需回退至 index.html 以支持刷新深链接。

### 授权先于业务请求

没有独立的系统存在性接口：通过所有系统分页接口以系统英文名为关键字，使用 `pageNum: 1`、`pageSize: 999` 查询，并精确匹配 `systemName`；候选超过一页时继续翻页，查完仍无匹配才返回 404，网络失败和取消不转换为不存在。鉴权统一使用所有系统查询：平台人员在系统存在时放行；普通用户仅在精确匹配记录的 `userRelation === true` 时放行，存在但未加入返回 403，未找到返回 404。不再为鉴权请求“我的系统”，网络失败和取消原样传播，旧目录缓存不参与放行。工作区保留完整匹配记录，包括 `userRelation`，以及接口可能额外返回的 `role`、`ystId`，不虚构缺失字段。切换器独立使用按用户隔离的“我的系统”缓存；已有目录在进入时复用，首次直达无目录时单独加载，挂载不重复请求。工作区只订阅用户标识和平台角色，并以浅比较避免姓名、部门等资料变化触发工作区更新。访问查询键包含系统、用户标识和平台角色，主动重新登录释放旧身份的业务缓存与在途查询。

工作区系统切换器不区分平台角色，始终只展示“我的系统”。平台人员从所有系统或直接 URL 进入未加入系统时，页头仍显示当前系统，但不将其追加到切换列表，也不虚构系统角色。

系统父路由挂载 `systemAccessMiddleware`，统一在并行父子 loader 前完成授权；业务 loader 只预取数据，不重复调用 `requireSystemAccess`。middleware 每次匹配系统路由都会执行，但仅在首次进入、刷新、跨系统、离开后重进、身份变化，或当前授权缺失、失败、被失效时请求最新授权。同系统切换应用、环境、创建/发布/检查快照、数据库页面及查询参数时，只要同身份的授权结果成功且未失效，就直接复用；不使用固定秒数缓存决定放行。同次表单导航的 action 与 loader 阶段在导航 context 中只记录已检查的查询键以去重，授权结果仍读取 Query；action 若失效授权查询，loader 前会重新校验。

`createSystemNavigationContext` 通过 Router 的 `getContext` 为每次导航快照已提交 `state.matches` 中的来源系统与恢复前身份。首次初始化没有已提交来源，按进入处理；POP、重定向和取消导航不使用浏览器地址或上次请求目标推断来源。导航取消后不继续业务 loader；共享在途授权可继续完成，但不会被记录成已进入系统，下次从工作区外进入仍重新校验。

授权用 `queryClient.query` 传播错误，不能用会吞掉失败的普通预取结果放行。普通页面预取使用 `query` 并显式消费错误，错误状态保留在缓存中，由页面展示和重试。middleware 与布局共用在途授权查询和缓存；`SystemLayout` 挂载不重复请求，窗口恢复焦点仍强制重新校验当前系统。成员或权限写入后须失效对应的 `system-access` 查询；最新 403 不因保留旧 data 而被导航复用。

接口返回 404 或 403 时展示对应状态，其他错误提供重试。系统访问查询的 403 优先于旧数据并移除 Outlet；HTTP 层仅传播错误，不再通过全局监听改写授权结果、批量取消请求或清除系统业务缓存。本期本地演示按平台角色和接口成员关系控制工作区入口；这不构成真实服务端安全边界，接入后端时所有业务读写接口仍须校验登录和授权。

### 状态与性能

Redux 管偏好和抽屉；Query 管系统列表、系统访问结果、应用与数据库类型；筛选、分页和创建表单留在页面。系统数据不复制到 Redux。

查询键使用系统和清单维度，loader、页面和侧栏共用唯一 QueryClient 与 query options。业务列表默认短时缓存；系统授权按工作区进入边界复用，不能用失败或已失效结果放行。查询 signal 传递给 Axios 与 Mock，写入后准确失效相关清单。

React 渲染纯净，不用 Effect 同步重复状态；外部订阅正确清理，selector 只订阅所需字段，不机械添加 memo。保留既有页面懒加载、分组虚拟滚动及列表写入锁，避免无依据重写树模型。

应用参数工具栏中，应用名称按内容自然占宽并限制最大宽度，长名称省略并提供完整提示。环境选项和操作按钮根据标题占宽后的实际剩余空间统一布局：先收起次要操作文字，再收起快照对比文字，仍不足时从末尾收纳环境到“更多”；“更多”文字也参与实测。展开预留 16px 缓冲，避免拖拽分栏时反复切换。隐藏测量区复用同一按钮结构，并预留已选数量徽标的宽度，收纳不改变环境选择和比对状态。操作按钮只对颜色、边框和阴影播放过渡，不对宽度、内边距或间距播放动画，避免应用切换重新挂载后首帧测量造成按钮伸缩闪动。

### Slice 与 thunk 接入

`src/store/index.ts` 负责注册 Slice 和创建 Store，沿用 Redux Toolkit 默认中间件，不配置 `extraArgument`。thunk 直接从 `src/api` 导入业务接口；请求地址、参数和 HTTP 调用留在 API 层，请求去重、取消及保存时序由 thunk 协调。

新增带 thunk 的 Slice 时，在 Store 注册 reducer，并使用 `src/store/createAppAsyncThunk.ts` 导出的 `createAppAsyncThunk`。它统一提供自动推导的 `RootState` 和 `AppDispatch`，支持 thunk 内派发其他 thunk；业务特有的 `rejectValue` 等类型在单个 thunk 上声明。该入口只配置类型，不封装业务流程。

创建 Store 仅接受启动显示选项，例如指定接口读取前的主题：

```ts
const store = createAppStore({
  themeMode: 'dark',
});
```

状态流程测试使用 Node 原生方法 mock 替换设置 API，并在测试结束后自动恢复；生产 Store 不提供测试服务注入参数。测试中的多个 Store 共用 API 实现，与多个页签访问同一个后端一致。偏好的保存队列与在途请求仍按 Store 隔离，取消一个 Store 不影响另一个。HTTP 与完整配置文档的契约测试继续调用实际接口实现。

默认的不可变与可序列化检查保持开启。启动主题只设置初始显示，不触发请求或保存。新增服务端业务清单继续由 TanStack Query 管理，不因支持 thunk 就复制到 Redux。

### ahooks 使用边界

局部交互使用 ahooks：`useEventListener` 管理拖拽、分栏快捷键及设置抽屉外部点击的监听生命周期，处理器读取最新状态，避免因闭包变化反复绑定；`useDebounceFn` 管理分栏悬停、列表定位高亮、拖拽悬停展开和保存提示的延迟任务，目标变化、关闭或卸载时取消；`useSize` 观察分栏容器，`useRafState` 合并横向滚动范围的同帧更新。保留拖拽末帧提交、焦点恢复与既有虚拟树模型。

主题外部订阅、工具栏多元素首帧测量、路由骨架按导航标识重计时，以及 HTTP 层的非组件监听继续保留原生实现。列表锁在重复提交时需要明确报错，不能直接替换成会静默跳过的 `useLockFn`；多列滚动范围仍需观察子元素，不能只用容器 `useSize` 推导。

统一从 `ahooks` 公共入口命名导入，兼容现有 Node/Vite SSR 测试环境；生产构建按需移除未使用导出。服务端请求、授权和缓存继续使用 TanStack Query，偏好保存继续使用现有 Redux 串行保存流程。

## HTTP 与 Mock 契约

所有 API 使用正常 Axios 请求，没有 `VITE_*` 控制真实/模拟调用。HTTP 层的 mockAdapter 是唯一接入点，按类别动态加载模拟模块，返回正常数据和 HTTP 状态。显式绝对 URL 走原生适配器，供真实 HTTP 契约测试使用。

| 方法与地址                                    | 请求/响应                                              |
| --------------------------------------------- | ------------------------------------------------------ |
| `GET /api/user-settings`                      | `{ userSetting: string }`                              |
| `PUT /api/user-settings`                      | 请求与响应均为完整 `{ userSetting: string }`           |
| `GET /api/systems`                            | 全量系统目录，包含 `userRelation`                      |
| `GET /api/systems/mine`                       | 我的系统数组，包含 `ystId`、`role`                     |
| `GET /api/systems/page`                       | 分页条件；响应 `{ records, total, pageNum, pageSize }` |
| `POST /api/systems`                           | 创建字段；响应创建后的系统                             |
| `GET /api/applications?systemName=...`        | 应用数组                                               |
| `GET /api/applications/groups?systemName=...` | `{ appGroupInfo: string                                | null }` |
| `PUT /api/applications/groups?systemName=...` | `{ appGroupInfo: string }`；204                        |
| `GET /api/parameters?systemName=...`          | 数据库类型数组                                         |

Mock 配置位于 `src/mocks/config.ts`，只包含请求延迟、应用数量和系统检索与业务访问错误，不包含登录身份。`src/mocks/systems.ts` 提供明确的系统关系夹具，独立存储在 `system-relations`，不读取旧系统存储里的遗留角色。`systemAccessError` 可设为 403、503 或 null，用于验证接口错误处理。

系统、系统关系、分组和显示设置使用版本化 localStorage，分组按系统共享，显示偏好按登录用户 `ystId` 保存到独立文档；禁用存储时回退内存。新系统返回空清单，系统统计与实际 Mock 数据一致。

`X-Mock-Error: load/save` 可模拟设置读取或保存失败；重复创建返回 409，不存在返回 404，尚未接入的删除明确返回失败。

接真实后端时，在 `src/http/request.ts` 将 adapter 改回 `['xhr', 'http']`，在 api 中调整实际地址和响应包装。登录业务由后续方案重新接入，不复用已删除的身份模型。

## 应用列表维护

GroupedList 的 UI、Hooks 和树模型在 `src/components/GroupedList`，页面私有 ApplicationList 绑定系统服务和业务配置。API 只维护清单/分组契约，queries 组装服务与缓存；不要让接口层依赖树 UI。

应用侧栏保留搜索、类型筛选、分组编辑、拖拽、选中定位和虚拟滚动，叶子使用 appName；右侧读取相同合并清单，分组不作为应用。数据库只读类型清单，不接旧参数分组或删除。

分组读写与刷新按系统和清单共用查询键及写入锁。写入期间暂停清单刷新，保存完成统一失效；显式刷新调用 queries/groupedList.ts 的 refreshGroupedList，而不是另建 QueryClient。清单失败有重试，最后订阅卸载时取消读取。

### 参数工作区职责

应用页与数据库页直接使用 `src/components/SplitPane/index.tsx` 组装 PC 分栏。`SplitPane` 只负责布局、侧栏收起、拖拽调整、键盘操作与尺寸记忆，不持有业务查询、环境选择或访问校验。

创建快照、发布和检查共用 `ApplicationOperationWorkspace`，消费相同的布局偏好：标准布局将标题栏和对比面板按 `gap-layout` 分开，面板圆角跟随全局设置；底部提示融入对比面板内部，使用主题浅色背景，并与正文共用外框和底部圆角。紧凑布局取消模块间距和面板外框，以分隔线衔接。操作页的外壳不把后台保留的配置分栏视为当前可见分栏，避免误用导航与应用列表的拼接样式。

- `src/pages/SystemApplications/index.tsx`：订阅当前系统的合并应用清单，根据 URL 的 `appName` 选择叶子，并持有按系统与应用绑定的环境选择。私有 `ApplicationList` 提供应用侧栏，`ApplicationParametersWorkspace.tsx` 提供空状态、工具栏和参数面板。
- `src/pages/DatabaseParameters/index.tsx`：查询数据库类型清单，根据 URL 的 `paramTypeName` 选择类型并处理请求反馈。私有 `components/ParameterTypeList.tsx` 负责搜索与导航，`components/ParameterTypeDetails.tsx` 展示类型详情与参数内容待接入提示。
- `src/components/CollectionSkeleton/index.tsx`：两个页面共用的首次数据等待骨架，只读各自已有的分栏尺寸缓存，保持与 PC 正文一致的分栏结构。

页面首次无数据时展示骨架；已有缓存的刷新保留工作区。URL 指定目标尚未在缓存中找到时，先等待刷新确认，失败保留错误与重试入口，成功后仍未找到才提示“不存在或已移除”。应用清单错误由应用侧栏展示，数据库清单错误由数据库页展示；业务清单组件不单独判断 403，既有系统访问校验由路由 loader 与 `SystemLayout` 负责。

创建快照、发布和检查是应用配置页的子路由，地址分别为 `application/:appName/:envTag/create/:version?`、`application/:appName/:envTag/publish/:version?` 和 `application/:appName/:envTag/inspect`。配置正文与操作页以绝对定位叠放在相同边界内，进入子操作时配置正文仅切换透明度，并通过 `inert`、`aria-hidden` 和禁用指针事件隔离后台交互；配置容器保持原尺寸，避免编辑器和工具栏因尺寸归零产生抖动。草稿、环境选择、分栏布局、滚动位置及 Monaco 实例和撤销历史保持不变；关闭或浏览器后退直接显示原正文。导航等待同样保留父页面，避免外层 `Activity` 隐藏时清理编辑器 Effect。同一应用往返沿用父 loader 的缓存策略，不因返回而重新挂载查询；显式刷新、写入失效及错误重试仍按原查询策略执行。离开应用区域、切换系统或系统访问失效后，配置页正常卸载；该缓存不跨浏览器刷新持久化。

## 样式、注释与验收

布局与控件优先 UnoCSS 和 Ant Design。全局主题只保留跨模块颜色、间距、圆角等语义；单个页面/组件的组合直接写工具类或私有常量。同一局部多次使用不等于全局复用。

品牌动画的专用关键帧在所属组件 model/animations.ts，就近内嵌最小 `<style>`；原因是 @keyframes 无法通过普通工具类定义。动画属性仍使用 UnoCSS，不新增 CSS 文件。现有 GroupedList.css 保留其现有复杂交互职责。

项目动效统一启用，不再跟随系统的“减少动态效果”偏好：首屏 HTML 与应用内图标共用不含 `motion-reduce` 禁用规则的组件；骨架、导航及控件过渡也移除对应工具类。`AppThemeProvider` 使用 `src/styles/motion.ts` 的 cssinjs 转换器，在 Ant Design 样式生成时移除 `prefers-reduced-motion: reduce` 分支，保留各控件原有动画和响应式规则，含挂载到 body 的弹层。此策略只处理项目和组件库主动禁用动效的规则，浏览器后台节流或不支持的动画特性仍由浏览器决定；图库的手动暂停功能保留。

全部 5 款加载方案的 SVG、轮廓和动画集中在 `src/components/LoadingIndicator`，启动 HTML 与应用内均使用 `<LoadingIndicator styleId={...} />`，无需区分图标系列；`UserLoadingIndicator` 只负责订阅 Redux 偏好。关键帧按当前方案内嵌，避免每个图标重复携带无关动画。

参数项图库保留 5 款加载方案，默认预览「品牌描边」（`data-trace`），按当前展示顺序连续编号；所有方案共用暂停、全局主题与 24/32/48/64px 尺寸预览。

用户设置的「外观 → 数据加载图标」与图库共用 `src/components/LoadingIndicator/model/styles.ts` 清单，可选择品牌描边、数据脉冲、点阵汇聚、彗尾流转和分合回弹。`loadingStyle` 使用稳定标识持久化，旧配置缺失时默认使用品牌描边（`data-trace`）；选择立即应用到全局 Ant Design Spin，并沿用设置串行保存、失败回退、重试、跨页签同步与恢复默认流程。图库预览保持独立，不修改用户偏好。

所有新增/实质重构模块添加中文职责说明；公共接口、关键类型、权限边界、缓存、并发与兼容行为解释原因，注释随实现更新。

回归重点：无用户信息依赖的启动与深链接、接口错误处理、创建与重复校验、设置字段保留及串行保存、取消后旧响应不恢复缓存、导航一致、生产图标、分组拖拽/虚拟化/分栏/主题。运行测试、构建、Lint、格式检查，并通过浏览器验证首页、创建、空状态、403 和两类工作区。

### 本地偏好按用户隔离

显示偏好 Mock 文档、主题/加载图标/控件圆角启动缓存、分栏宽度与折叠状态，以及跨页签设置通知通道均以 `ystId` 隔离；同一人的平台角色、网络环境变化不产生另一份偏好。缓存键使用资源键加 `:user:<编码后的 ystId>`，未登录使用独立的 `:anonymous` 空间。不读取、迁移或自动删除旧公共键。系统和系统分组等共享业务数据继续按原业务维度保存。

登录和退出均整页替换，重新建立用户的状态与请求生命周期。其他页签修改或清除登录记录时，当前页签通过 storage 事件及恢复焦点检查取消设置请求、释放查询缓存并重载；HMR 会移除这些监听。设置请求在 Mock 延迟前固定用户文档键，启动缓存与分栏写入也校验所属用户，避免切换期间旧数据写入另一账号。退出保留各用户偏好，重新登录后恢复。此命名空间只隔离使用体验，实际登录和授权仍需服务端校验。
