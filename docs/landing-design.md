## 一、定位与目标

### 1. 页面定位

面向行内开发人员的技术产品介绍与接入入口。通过具体的参数变更场景，说明灵动参数管家如何降低修改风险、提升操作效率，并引导用户进入控制台或阅读接入指南。

实际产品页为 `/landing`，实现入口为 `src/pages/Landing/index.tsx`。官网品牌、图片、评价与页面内容不作为本产品素材。

页面可匿名阅读；进入控制台后的登录与系统授权沿用现有流程。公开路由表示页面无需登录，不表示行内资料可以发布到互联网。

### 2. 目标用户与任务

| 用户                   | 需要回答的问题                       | 页面提供的出口               |
| ---------------------- | ------------------------------------ | ---------------------------- |
| 首次了解产品的开发人员 | 能解决什么问题，是否适合我的应用？   | 核心能力、接入指南           |
| 计划接入的应用负责人   | 怎么接入，需要哪些改造，有什么前提？ | 架构说明、框架文档、支持入口 |
| 已接入的开发人员       | 从哪里进入工具，如何查询操作方法？   | 进入控制台、详细文档         |

### 3. 核心表达与行动

主张：**让每一次参数变更，更可控。**

叙事主线：**发布前发现问题 → 发布时掌握变化 → 发布后确认生效。**

主行动统一命名为“进入控制台”，次行动统一命名为“查看接入指南”。导航、首屏和页尾保持相同名称及目的地。首版不增加注册、预约销售、价格套餐或收集个人信息的表单。

用户应能在首屏理解产品用途；继续阅读后能解释快照流程、识别接入条件并找到对应文档。这些是可用性验证目标，不是已经取得的结果。

### 5. 参数变更流程

**标题：从参数修改到生效，每一步都有依据。**

1. **保存参数**：集中维护业务应用与公共模块配置。
2. **生成快照**：合并配置，保留某一版本的完整参数。
3. **发布快照**：将选定版本发布到配置中心，历史版本可用于回退。
4. **确认生效**：按应用条件重启或热更新，并查看运行时参数差异。

第 4 步中明确：热更新有接入与代码条件，不表示发布后所有实例自动生效。生产发布受现有权限流程约束，不从“一键发布”推导成免授权操作。

桌面左侧纵向步骤、右侧详情面板，窄屏按顺序全部展开；步骤序号仅用于真实流程顺序。不自动循环模拟发布，点击只切换讲解。桌面每一步的标题与摘要常驻，详细示意按选择显示；窄屏完整内容直接可读。

## 五、视觉规范

### 1. 设计方向

推荐“参数变更工作台”：以真实参数差异、版本关系与检查结果作为视觉主体。强调可读性、操作秩序与工程可信度，品牌记忆集中在首屏产品预览；其余区域保持安静。

首版支持浅色、深色、跟随系统三种主题模式，在导航提供明确切换入口。复用平台已有 themeMode 偏好与主题 Provider，落地页和控制台使用同一选择；已有设置优先，没有有效选择时默认跟随系统。浅色与深色均为完整设计与验收目标。主色、语义状态色及明暗模式继续由平台主题提供；文字、背景、边框、表面及阴影参考 React Bits 官网首页，在落地页根容器以局部变量映射维护，不更改后台全局中性色。详细交互与保存规则见第十四节，首页参考和头部行为见第十五节。

| 辅助文字   | `#52525b`             | `#aaaaaa`      | 初始参考，最终按实际背景核对对比度                       |
| 轻边界     | `#18181b12`           | `#ffffff0e`    | 只用于装饰分界；必要交互边界另行加强                     |
| 毛玻璃表面 | `#ffffffc2`           | `#120f1773`    | 用于收拢头部和菜单；不支持模糊时回退可读的不透明表面     |

以上文字与画布参考值来自 2026-11-05 直接读取的官网 CSS，毛玻璃值来自官网导航规则；不是从复刻页取值。官网全局卡片浅色为 #ffffff、抬升表面为 #f1f1f2，深色卡片为 #1b1722；页面按实际层级选用。局部边界的半透明值为产品设计候选，不冒充官网全局 token；官网全局 border-subtle 为浅色 #e7e7e9、深色 #2f293a。

通过落地页根元素的局部 CSS 变量映射到 UnoCSS 语义名，不调用全局 applyTheme 改写中性色。平台主色、成功/警告/错误等语义色仍由 src/styles/theme.ts 提供，继续复用已有 Provider。对比度按实际表面核对，不机械复制装饰色作为正文。

### 4. 布局与响应式

内容容器最大宽度为 **1280px**，按 border-box 计算并包含容器内边距；宽屏居中，容器内桌面左右留白 32px，窄屏 20px。导航、正文和页脚共用此宽度上限，全幅背景可延伸至视口两侧。基于 8px 间距组织，正文内间距 12–24px，区块间距桌面 88–112px、窄屏 56–72px。信息面板圆角建议 12–16px，按钮优先采用所选 React Bits 组件并统一局部圆角；不为所有层级套同一张卡片。

响应式范围仅用于落地页，不扩展后台业务工作区的移动端支持。下列为布局设计区间，UnoCSS 实施使用局部任意宽度变体，不假定已配置 sm/md/lg：

| <768px     | 单列叙事，文案在预览之前，流程竖排，按钮可换行         |

## 六、React Bits 与交互规范

### 组件使用原则

实际产品落地页的组件尽量采用 React Bits，范围包括导航、按钮、展示卡片、背景和适用的内容交互，不限于背景特效。页面及其私有组件不直接引入 Ant Design，也不通过包装组件间接使用 Ant Design。应用现有全局 Provider 和主题变量可继续复用，不为此改动后台业务页面。

具体组件与适配要求见第十一节。开发时先通过 shadcn MCP 定位，再核对官方源码、依赖、交互语义及许可，不能把视觉相似当作功能兼容。优先采用或适配满足需求的 React Bits 组件；缺少适合的组件时，以语义化原生元素和 UnoCSS 补齐。例如 FAQ 可使用原生 details/summary，导航链接使用 a，操作按钮使用 button。不得为追求组件覆盖率牺牲阅读、键盘操作或性能。

组件复用不意味着同时开启所有默认动效。导航、按钮和卡片可以保留结构及视觉特征，按页面叙事收敛动画；仍遵守单一首屏视觉焦点与下列动效规范。

### 1. 动效选型

首屏采用独立实现的“点阵流体背景”方案，参考 React Bits Pro 首页的公开视觉与交互：浅色点阵、缓慢流动的紫色墨迹、鼠标扰动和文字区域渐隐。不直接复制、反编译还原官网打包代码，也不冒用 `FluidDotField` 官方组件身份。没有确认可获取的官方原始源码及复用许可；本方案属于页面私有实现，设计阶段不安装依赖。

视觉意图是低饱和、低亮度、慢速流动，主体区域为产品预览周边。正文与按钮使用稳定表面，背景不覆盖文字；静态点阵降级也应表达同样层级。背景铺满首屏视口宽度，内容保持 1280px 上限。最终颜色和速度在真实设备预览中确定。

若流体影响文字阅读或性能，使用静态点阵。Aurora 和 Waves 不再是首版主方案，不与点阵流体叠加。首版不采用 AcidSquares 的强反光表面、不添加粒子光标、逐字标题动画或全页区块入场动画。

### 2. 动态内容行为

- 主标题、正文和按钮无需等待动画即可显示；不接管原生滚动。
- 自动背景提供键盘可操作的暂停/继续入口；离屏或页面隐藏时暂停，资源加载失败时回退静态背景。
- 首版沿用项目现有动效策略，不在本次开发改变全局或单独增加系统偏好覆盖。背景始终提供手动暂停，离屏和文档隐藏时暂停；可访问性检查按实际结果记录，不据此宣称整体符合 WCAG AA。
- 菜单、折叠面板和焦点反馈采用简短过渡，建议 150–250ms；滚动过程不触发大面积缩放、闪烁或连续自动切换。
- 菜单、按钮、卡片和适用交互优先采用 React Bits，布局使用 UnoCSS；本页不使用 Ant Design。核对所选组件的键盘、焦点和状态语义，缺失时补齐；没有合适组件时使用语义化原生元素。
- 原型中的流程切换只更新说明与示意图；不进行真实参数写入、发布或回退。

## 七、可访问性与性能目标

### 1. 可访问性

以 WCAG 2.2 AA 相关要求作为检查依据，不在完成检查前宣称认证或全面符合。普通正文对比度至少 4.5:1，大号文本至少 3:1；可操作边界和必要状态指示按非文本对比要求检查。依据：[W3C WCAG 快速参考](https://www.w3.org/WAI/WCAG22/quickref/)。

提供清晰的标题层级和单一 H1；按钮及链接有明确名称，支持键盘操作和可见焦点。吸顶导航不得遮住焦点。页面允许文字放大与重排；装饰画布不参与辅助技术阅读，有信息的截图提供替代说明。差异与异常同时使用文字或符号，不能仅依赖颜色。菜单支持 Escape 关闭并将焦点返回触发点。

### 2. 性能

目标参考 Core Web Vitals：LCP ≤2.5s、INP ≤200ms、CLS ≤0.1，以移动端和桌面真实访问分别统计的第 75 百分位判断；本地实验室结果只能作为开发参考。依据：[web.dev Web Vitals](https://web.dev/articles/vitals)。

首屏文案与行动先呈现；背景作为可延迟的增强。图片声明尺寸，首屏关键图及时加载，后续图按需加载。不为展示代码引入 Monaco，不为关系示意引入图形引擎，不加载复刻页素材。现有首屏构建预算继续执行；记录新增依赖与页面产物变化，并检查动画开启时的滚动及交互。

所有动画帧、监听器、观察器与 GPU 资源在卸载时清理，并验证 StrictMode 重挂载、窗口尺寸变化和页面往返。静态内容不引入额外 API、Redux 状态或查询缓存；主题仍复用既有偏好请求与 Redux，区块选择和面板状态留在页面内。

## 十四、主题切换设计

### 1. 模式与默认值

| 模式     | 展示行为                                   |
| -------- | ------------------------------------------ |
| 浅色     | 固定浅色，不随操作系统外观变化             |
| 深色     | 固定深色，不随操作系统外观变化             |
| 跟随系统 | 根据系统外观显示浅色或深色，并响应后续变化 |

已有有效用户选择优先，无有效选择时采用项目默认 system。跟随系统仍保存为 system，不把解析后的 light/dark 覆盖到偏好。无法读取系统外观时回退浅色。

这是平台主题偏好的新增入口：从落地页进入控制台后继续沿用所选主题；返回落地页也沿用平台设置。不会修改编辑器的 theme 字段。

### 2. 桌面入口

导航右侧、“进入控制台”之前放置“外观”按钮，图标随当前模式显示太阳、月亮或系统；可访问名称包含当前选择，例如“外观：跟随系统”。显示所选模式，而不把 system 只渲染成当前实际明暗状态。

点击打开小型选择面板，三项文案为“浅色”“深色”“跟随系统”。使用原生按钮和单选组语义，由 UnoCSS 排版，不使用 Ant Design。独立头部的导航与外观选择分工明确；当前没有核对到更合适的 React Bits 主题选择组件，不额外引入组件库。

选中项有文字/勾选状态及清晰焦点。面板支持键盘、Escape 关闭并返回触发按钮，点击外部关闭；选择后即时应用并关闭面板。保存失败时提供可感知的短提示，不仅使用颜色。

### 3. 窄屏入口

主题选择放在导航展开菜单中，标签“外观”，下方三项单选，点击目标不低于既有 44px 建议高度。选择主题不会误触控制台跳转或关闭整个页面；菜单的开关和焦点行为保持一致。布局拥挤时优先折叠区块导航，不挤掉控制台入口。

### 4. 各区域适配

| 区域               | 浅色处理                             | 深色处理                                         |
| ------------------ | ------------------------------------ | ------------------------------------------------ |
| 页面与导航         | 参考官网首页浅色中性画布与文字       | 参考官网首页深色中性画布，保留表面层级           |
| 点阵流体           | 灰点与稀薄紫色墨迹，标题区域减弱背景 | 降低墨迹亮度，避免亮点覆盖文字；暂停状态保持不变 |
| 独立头部与主行动   | 使用平台浅色主题对应的强调与焦点色   | 使用平台暗色强调色，核对按钮文字对比度           |
| 产品预览和能力卡片 | 可读表面与低强度高光                 | 分层深色表面，重新校准边缘高光，不简单反相       |

| 参数差异与状态     | 增删、警告配文字及符号               | 单独核对语义色对比，不依赖原图颜色自动反转       |

主题变化不得重置当前流程步骤、FAQ 展开、菜单状态、滚动位置或背景暂停选择。流体更新颜色时保留已有资源和指针状态，避免因主题切换重复创建画布及事件监听；不以主题作为整页重新挂载的 key。

若使用真实截图，需要准备对应明暗版本或给图片设置稳定展示边框与背景，不能用 CSS 滤镜简单反相。优先使用可响应主题的 HTML 示意画面。

### 5. 状态、保存与失败反馈

复用 Redux 中的 preferences.themeMode、useResolvedTheme、AppThemeProvider 和现有 saveThemeMode/saveUserSettings 流程。页面按字段订阅，不另建本地主题副本、全局 Context 或独立存储键。实际持久化通过现有设置管线完成，不在渲染或 reducer 中写 localStorage。

保留现有串行保存、乐观更新、失败回退和旧响应保护。快速连续选择时，以最后一次有效选择为目标；失败反馈文案建议“主题保存失败，已恢复上次设置”，提供“重试”，具体回退范围与现有状态机一致。保存中仍允许继续选择，不把整个页面置为加载态。

登录身份与匿名命名空间沿用现有偏好隔离约定，不将匿名偏好写入另一用户，不新增绕过既有管线的存储或请求。匿名读取/保存与刷新行为需在实施时验证，不把已存在命名空间当作完整行为已经验证。

首屏继续复用现有主题启动缓存，目标是直接呈现缓存对应的画布与文字颜色；不得等待落地页懒加载后才首次设置主题。已登录身份变化、缓存不可用、存储受限等情况遵循既有回退并验证；不宣称已经消除所有闪烁。

颜色过渡可在主题表面、边框和文字上采用约 150–200ms 的局部过渡，不添加整页旋转、圆形扩散或遮挡式转场。布局尺寸和阅读位置不随主题变化，首屏流体不闪白。

- [ ] 三个模式的选择、图标、文案与实际配色一致，system 模式能响应系统变化。
- [ ] 固定浅色/深色时系统变化不覆盖用户选择，刷新和控制台往返保持既有偏好行为。
- [ ] 桌面面板、窄屏菜单、键盘、焦点返回和单选状态可用。
- [ ] 快速选择、保存失败与重试保持现有串行和回退逻辑，身份切换不串用设置。
- [ ] 明暗主题下核对正文、日期、按钮、状态、焦点和全部示意数据的对比度。
- [ ] 背景暂停、步骤、FAQ 与滚动状态不因主题切换重置，无重复监听或画布泄漏。

### 2. 文字与表面层级

首屏点阵流体仍保留已确定方案，官网首页的整体风格参考不意味着换回波浪背景。紫色流体作为局部装饰，不替换平台按钮主色；产品状态使用平台语义色。主题切换同时更新局部中性变量与继承的强调色，避免只切主色或出现深底深字。

不修改后台的 Dracula 中性色；落地页自行维护两套局部中性表面映射，明暗选择仍来自唯一的 themeMode。页面内菜单与外观面板优先置于局部主题根节点内；需要挂载到外部时明确携带相同变量，不依赖错误的全局背景。

### 3. 桌面头部状态

| 状态          | 官网资源已确认                                                                  | 产品适配要求                                                                                                          |
| ------------- | ------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 首屏展开      | 顶部 20px、内栏高 56px、最大宽度 1680px、透明背景                               | 保留透明与固定位置，遵守产品最大宽度 1280px                                                                           |
| 滚动收拢      | window.scrollY > 50，最大宽度变为 1276px，出现毛玻璃、边框及阴影，高度仍为 56px | 按产品实际滚动容器监听；收拢宽度暂建议 1120px，使 1280px 约束下仍可感知收拢，此值是产品适配方案，待官网视觉对照后校准 |
| 返回顶部      | scrollY ≤50 恢复原状态，没有从源码确认到 24px 回退阈值                          | 同步采用 50px 阈值，不保留此前无依据的 40/24px 方案                                                                   |
| 菜单/外观面板 | 官网首页提供局部浮层及二态主题按钮                                              | 产品保留三态主题选择；菜单/主题面板互斥、保持可读背景，这些属于产品交互补充                                           |
| 明暗切换      | 官网有独立明暗样式                                                              | 复用平台三态偏好，保持菜单、流程及滚动状态                                                                            |

1280px 是产品所有头部状态的上限，不照搬官网 1680px 的展开宽度。宽度不足时优先折叠区块导航，不能为了收拢效果挤压品牌、外观与控制台入口。1120px 不是官网尺寸，不作为像素级还原结论。

收拢过渡以官网 0.5s ease 为起点，明确指定 max-width、背景、边框和内边距等相关属性，不使用 transition-all，不添加高度或字号缩放。固定头部不推动正文。高频滚动只在状态跨阈值后更新，不逐像素驱动整页渲染。

### 4. 悬停、焦点与面板

**共享高亮底板为头部必须实现的关键效果。** 不为每个链接各自绘制无法跨项移动的 hover 背景。进入任一项时底板从当前位置滑到目标并匹配其宽度，移出导航后滑回活动项或淡出；键盘 focus 同样驱动底板。官网脚本按路由确定活动项，产品按本页区块位置确定活动项，这属于适配差异。高亮底板保留官网中性毛玻璃风格，必要焦点轮廓使用平台主色，不叠加文字翻滚、粒子和流光。

外观按钮保留第十四节的三种模式选择；面板位于按钮下方，不超出视口，可用 Escape 关闭，关闭后返回触发点。外观面板与移动导航互斥，避免重叠和焦点混乱。

控制台主行动在导航中采用平台主色和清晰 focus-visible 轮廓，不改变“进入控制台”的目的地。菜单及链接点击不被点阵画布拦截。

### 5. 窄屏与兼容

窄屏左右约 16–20px 安全间距、顶部默认按官网 20px 起点校准，头部高约 56px，保留品牌、控制台、菜单三项。展开菜单参考官网营销首页的局部浮层：位于头部下方约 8px，靠右对齐，使用局部主题表面，长内容在面板内可滚动，不能越出视口。不套用官网文档页全屏菜单；三线转叉与菜单短入场纳入直接官网对照范围。

首屏透明状态打开菜单时立即提供稳定底色；点击锚点关闭菜单并滚动到正确区块。Escape、外部点击、断点切换和页面卸载需要清理相关状态与监听。键盘目标保持不低于既有建议尺寸，视觉上较小的图标也要保留足够可操作区域。

不支持 backdrop-filter 时回退不透明表面，确保任何首屏背景下都可读；不因模糊不可用而隐藏导航。减少动态效果策略按既有页面约定处理，收拢仍能直接到达清晰状态。

### 2. 滚动、活动项与焦点边界

遵循当前 AppViewport 的全高布局，以 Landing 根容器作为唯一页面滚动容器；不同时创建 window 与内部两套滚动。头部收拢使用该容器的 scrollTop > 50，活动区块观察器使用同一 root。直接访问带锚点的地址、点击导航、返回顶部及浏览器前进后退均验证滚动定位，标题预留约 104px 的顶部间距。

首屏与统计区无导航活动项，进入对应目标区块后才有活动项；到页尾继续保留 FAQ 为最后活动项。鼠标悬停或键盘焦点覆盖当前活动项的高亮位置，离开后二者都不存在时恢复活动项或淡出。收拢动画、字体完成加载、视口变化及导航文字变化后重新测量底板，不只在首次 hover 测量。避免 ResizeObserver 回调中反复触发布局循环。

窄屏菜单和外观面板互斥：菜单内的外观单选是内嵌内容，不再嵌套第二个浮层。主题选择后可保留移动菜单，点击区块链接后关闭菜单。桌面面板 Escape 关闭后返回触发器；点击外部关闭时不强行抢回用户已点击元素的焦点。

### 3. MagicBento 适配边界

核心能力采用一大两小网格，架构采用三张等宽卡片，文档入口采用两张卡片，卡片内容全部来自本产品。源码若将演示数据固定在内部，进行局部内容插槽/数据适配，不为此建立全站通用卡片引擎。不同布局是页面内组合，不修改全局 UnoCSS shortcuts。

保留克制边缘高光；首版不启用装饰粒子、3D 倾斜、点击爆发或自动旋转。它是展示容器，不替代内部表格、链接、列表的语义。不将每张卡片整块设为按钮，文档卡保留一个明确链接。

MCP 已确认组件存在及概要，但完整源码与额外依赖仍需引入时核对。如果无法获取适用源码，保留内容并记录获取失败，不能把独立实现的卡片写成已采用官方 MagicBento，也不默默切回全页 SpotlightCard 方案。

### 4. 主题与启动兼容

复用既有初始化与设置状态机，不在本次任务重写全局启动。当前 App 在偏好初始化结束前仍展示原有等待界面，读取失败后可能显示全局 Ant Design 警告；这属于既有根外壳行为。页面及其私有组件不新增 Ant Design 控件，不能将此要求解释为本任务必须移除全局 Provider 或重构根错误提示。

主题读取失败或设置 JSON 无效时，不能因 initialized 已结束就自动覆盖保存；是否允许选择与提交遵守现有状态机校验。主题面板应反映无法保存的原因，保留已有重试路径。匿名与已登录的选择、快速保存及失败回退均作为本次集成验证项。

全局 HTML 启动缓存配色与落地页局部中性色不保证完全相同；初始要求是按缓存选择正确的明暗模式，页面挂载时补齐局部色，不出现反向主题闪烁。若调整 HTML 启动层，应单独评估影响并执行完整检查，不为微小色差扩大重构。

### 5. 页面元信息与目录

页面标题建议为“灵动参数管家｜让参数变更更可控”，描述采用首屏介绍的简洁版本。进入和离开落地页应正确设置与恢复元信息，语言按中文处理。当前不新增第三方埋点、搜索引擎预渲染或发布部署流程。
